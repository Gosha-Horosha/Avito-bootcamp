# Поиск кандидатов для запросов в услугах Авито

Для каждого из 2 452 поисковых запросов нужно выбрать 50 объявлений из 189 тысяч так, чтобы среди них
оказались те, которые пользователь действительно выбрал. Качество — Recall@50: какая доля правильных
объявлений попала в эти 50.

Всё решение — в ноутбуке [`notebooks/04_solution.ipynb`](notebooks/04_solution.ipynb): от загрузки данных до
файла ответа, с пояснением каждого шага. Здесь — краткое содержание и выводы.

## Результат

| | Recall@50 на валидации |
|---|---|
| **итоговое решение** (взвешенная сумма методов + CatBoost) | **0.845** |
| только взвешенная сумма методов | 0.838 |
| потолок: правильных ответов среди отобранных кандидатов | 0.943 |

## Как устроено решение

Поиск идёт в две ступени.

1. **Отбор кандидатов.** Каждое объявление оценивается несколькими методами (они перечислены ниже). Лучшие
   объявления по каждому методу объединяются в список примерно из 700 кандидатов на запрос. Методы ошибаются
   по-разному, поэтому вместе теряют мало: в этом списке 94% правильных ответов.
2. **Выбор 50 из кандидатов.** Оценки методов складываются с весами, подобранными на валидации. Затем модель
   CatBoost, обученная расставлять кандидатов по порядку, пересортировывает 200 лучших. Она учитывает то, чего
   не видит простая сумма: сочетания оценок и свойства объявлений — число отзывов, длину описания, цену.

## Какие данные использованы и почему

Методы оценки объявления для запроса:

- **Слова запроса в заголовке и описании** (формула BM25, слова приведены к начальной форме). Главный метод:
  описание нужно, потому что у многих правильных объявлений короткий общий заголовок вроде «Бетонные работы».
- **Смысловая близость** — готовая нейросеть `multilingual-e5-base`, без дообучения. Находит объявления без
  общих с запросом слов: «отделочные работы» → «ремонт квартир под ключ».
- **Похожие кусочки слов** в заголовке — защита от опечаток и необычных форм слов.
- **Фильтр запроса** — совпадение выбранного пользователем вида/типа услуги с тем же полем объявления.
- **Микрокатегория** — какие микрокатегории выбирали люди по похожим запросам в train. Сами объявления
  бенчмарка почти не встречаются в train (общих 9.6%), а микрокатегории у них те же — так опыт train
  переносится на новые объявления.
- **Место** — совпадение локации и расстояние до неё. 82% выбранных объявлений находятся в той же локации,
  что и запрос, остальные — чаще всего в соседних городах: люди ищут исполнителя рядом. Поэтому близкие
  объявления получают бонус, который плавно убывает с расстоянием. Фильтровать по городу нельзя — потерялись
  бы 18% правильных ответов.

Не используются: категория запроса (почти всегда одна и та же, сигнала в ней нет) и остальные параметры
объявления вроде графика работы и адреса — они только добавляют шум в текст.

**Что даёт каждый метод** — насколько падает качество, если его убрать:

| что убрали | Recall@50 |
|---|---|
| ничего | 0.838 |
| место (расстояние) | 0.731 |
| слова в заголовке и описании | 0.747 |
| место (совпадение локации) | 0.803 |
| смысловая близость | 0.823 |
| фильтр запроса | 0.826 |
| микрокатегория | 0.827 |
| похожие кусочки слов | 0.837 |

**Вывод:** решение держится на двух вещах — на совпадении слов с учётом описания и на месте. Смысловая
близость, фильтр запроса и микрокатегория добавляют по 1–1.5 процентного пункта, похожие кусочки слов — почти
ничего.

## Как проверялось качество

Правильных ответов для бенчмарка нет, поэтому часть запросов train откладывается, и для них ищутся объявления
среди всех 345 тысяч объявлений train. Чтобы проверка была похожа на бенчмарк:

- **Запрос — это текст вместе с локацией и фильтрами.** «Маникюр» в Москве и в Казани — разные запросы.
- **Один запрос на каждый текст.** В train популярный текст вроде «маникюр» повторяется в сотнях городов, а в
  бенчмарке каждый текст встречается один раз. Без этой поправки оценку определяли бы несколько популярных
  текстов.
- **Столько же знакомых текстов, как в бенчмарке.** 37% текстов бенчмарка встречались в train; при подсчёте
  качества их доля приводится к тем же 37%.
- **Веса проверены на переобучение.** Веса, подобранные на одной половине проверочных запросов, дают на
  другой половине почти то же качество (0.833 и 0.838 против 0.837 и 0.838). Сами половины различаются примерно на 0.005 — улучшения меньше этой
  величины считаются случайными. CatBoost выигрывает 0.007, поэтому он вошёл в решение.

## Какие ошибки находили и что с ними сделали

| ошибка | пример | что сделано |
|---|---|---|
| разные формы слова | «телевизор» и «телевизора» | слова приводятся к начальной форме |
| у правильного объявления короткий общий заголовок | «Бетонные работы» на запрос «заливка бетонных дорожек» | поиск слов и в описании |
| синонимы без общих слов | «отделочные работы» → «Ремонт квартир и офисов под ключ» | смысловая близость |
| общие слова дают ложное совпадение | «услуги», «ГОСТ» | редкие слова весят больше частых, учитывается фильтр запроса |
| правильное объявление в соседнем городе | выезд мастера | бонус за близость вместо фильтра по городу |
| в корпусе нет ни одного объявления из города запроса | 17% запросов бенчмарка | координаты городов берутся и из train |
| такое же объявление в другом городе | одинаковые «Аренда прицепа…» в разных городах | не исправить: 40% заголовков повторяются |

Что пробовали и отказались — набирать 50 «лучших по каждому методу» вместо общей оценки, Word2Vec вместо
нейросети e5, подбор весов логистической регрессией: всё это оказалось хуже. Путь от первого варианта
(поиск по словам заголовка, Recall@50 = 0.155 на ранней, упрощённой проверке) к итоговому — в
[`notebooks/02_experiments.ipynb`](notebooks/02_experiments.ipynb).

## Как запустить

1. Положить в папку `dataset/` файлы `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet`.
2. Установить зависимости: `uv sync` (версии всех библиотек закреплены в `uv.lock`).
3. Выполнить `notebooks/04_solution.ipynb` целиком.

Модель e5 (~1 ГБ) скачивается автоматически при первом запуске; можно скачать заранее:

```bash
hf download intfloat/multilingual-e5-base --local-dir artifacts/e5_baseline/multilingual-e5-base
```

Ответ появится в `submissions/answer_NN.csv` — каждый запуск создаёт новый файл, старые не перезаписываются.

**Сколько ждать** (видеокарта GTX 1650, 16 ГБ памяти): первый запуск — около полутора часов, из них ~35 минут
уходит на обработку объявлений нейросетью. Промежуточные результаты сохраняются в `artifacts/cache`, поэтому
повторный запуск занимает ~20 минут.

**Одинаковый ли результат при повторе.** Да: на одной машине два полных прогона дали побайтово одинаковый файл.
Все случайные шаги зафиксированы, версии библиотек закреплены в `uv.lock`. На другом компьютере вычисления
нейросети могут отличаться в последних знаках, и несколько объявлений на границе первой полусотни могут
поменяться местами. Если положить отправленный файл в `submissions/submitted.csv`, ноутбук покажет, какая доля
ответа совпала.

## Модели и библиотеки

- `intfloat/multilingual-e5-base` (Hugging Face, лицензия MIT) — смысловая близость, без дообучения;
- CatBoost — сортировка кандидатов;
- pymorphy2 — приведение слов к начальной форме;
- scikit-learn, scipy — поиск по словам и кусочкам слов;
- PyTorch, sentence-transformers — работа нейросети;
- pandas, numpy, pyarrow — работа с данными.

## Ограничения и что можно улучшить

- Проверка идёт на объявлениях train (345 тысяч), а в бенчмарке их 189 тысяч, поэтому результат на
  лидерборде будет другим.
- Нейросеть видит только заголовок и вид услуги: с описаниями обработка заняла бы около 5 часов на этой
  видеокарте. Описания и так учитываются поиском по словам.
- Можно дообучить нейросеть на парах «запрос — выбранное объявление» из train и дать CatBoost больше данных о
  популярности объявлений в каждом городе.
